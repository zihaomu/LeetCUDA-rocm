# B3：11个MMA/CuTe HGEMM移植与验收

更新时间：2026-11-05。状态：B3的11个入口功能验收完成；正式支持186/229（81.22%），性能继续单列。

## 精度与存储契约

这11个原接口均采用明确的精度升级：FP16输入/输出，原NVIDIA FP16累加改为AMD WMMA FP32累加。没有放宽atol=rtol=0.01，也不宣称FP16 MMA逐位仿真。

TN入口保持原存储约定：B的Tensor形状为[K,N]，其连续存储按[N,K]解释。非方阵、未对齐连续视图和长K分别验证。stage参数保持原缺省映射：静态stage与CuTe只支持2/3/4；其他支持2/3/4/5；范围外值映射2。block swizzle具有实际三维grid映射。

## 新增接口与实际机制

| 接口 | AMD实现 |
| --- | --- |
| `hgemm_mma_m16n8k16_naive` | 16×8输出，原始全局装载；使用16×16 AMD矩阵指令，屏蔽额外列 |
| `hgemm_mma_m16n8k16_mma2x4_warp4x4` | 128×128 CTA，K16静态LDS |
| `hgemm_mma_m16n8k16_mma2x4_warp4x4_stages` | K16静态LDS ring，stage2/3/4 |
| `hgemm_mma_m16n8k16_mma2x4_warp4x4_stages_dsmem` | K16动态LDS ring，stage2/3/4/5 |
| `hgemm_mma_m16n8k16_mma2x4_warp4x4x2_stages_dsmem` | K32与两个寄存器K片段、动态stage |
| `hgemm_mma_m16n8k16_mma2x4_warp4x4x2_stages_dsmem_x4` | K32配对布局，H16宽LDS读一次取得两个K片段 |
| `hgemm_mma_m16n8k16_mma2x4_warp4x4x2_stages_dsmem_rr` | K32，每次只保持一个B片段，减少临时寄存器生命周期 |
| `hgemm_mma_m16n8k16_mma2x4_warp4x4x2_stages_dsmem_swizzle` | K32，A/B实际XOR LDS布局 |
| `hgemm_mma_m16n8k16_mma2x4_warp4x4_stages_dsmem_tn` | K16，原packed TN存储与动态LDS |
| `hgemm_mma_m16n8k16_mma2x4_warp4x4x2_stages_dsmem_tn_swizzle_x4` | K32，packed TN、XOR布局、配对宽LDS读 |
| `hgemm_mma_stages_block_swizzle_tn_cute` | 重写CuTe的TN分块/拷贝/布局；stage2为128×256，stage3/4为128×128 |

K32的stage5统一采用64×128 CTA，其余一般128×128；CuTe stage3/4缩小N分块。保留stage深度，使每CTA LDS≤64KiB。CuTe stage3/4在此资源适配后使用与TN宽布局相同的AMD几何；stage2仍有独立256列分块。

## 正确性与资源证据

- 两张AMD卡各2947项：360共享输入、2587边界/契约/stream/device/精度状态检查全部通过。
- 包含两个种子、K4096与边界K8193、空M/N/K、奇数tile、TN非方阵、canary、八条stream、非法契约与device guard。
- 36项精确FP32累加状态检查：构造输出16.125，原逐块FP16累加为16.0。
- 36个特化全部使用AMD WMMA、无scratch spill，LDS最多65536字节。
- rr在stage2/3/4的VGPR为136/128/137，普通x2对应163/155/164。stage5 rr的编译器未保留静态load→WMMA→wait顺序，不据此宣称该配置有硬件重叠收益。
- 全库24模块、186接口、1048项通过；新增55个GEMM tile检查和22个基础检查。

原CUDA保持原计算源码，仅将launch适配到当前stream，360项中：**256通过、64项K4096精度失败、40项stage5资源拒绝**。AMD360/360通过；256组跨平台在同一门限内，其他差异与显式精度升级/原资源错误分开记录。

原CUDA资源错误已真实复现并保留两次日志：普通x2/x4/rr的stage5申请104960字节，TN swizzle x4申请102400字节，超过封装设置98304字节，也超过5090单CTA opt-in上限101376字节。随后对这40项按已确认资源公式预检查，记录executed=false和失败原因，没有伪造输出。

全库首次集成的15个TN检查失败来自旧测试把所有B当NN计算；修复独立参考为原TN约定，保留第一次失败报告。

全接口186个入口的376组共享输入在AMD与CUDA ported端均通过独立参考，376/376跨平台容差通过。这个小尺寸回归不覆盖原FP16长K问题，上述扩大专项结论保持不变。
