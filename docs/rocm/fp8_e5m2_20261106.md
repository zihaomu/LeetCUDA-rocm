# FP8 E5M2 完整链路与 E4M3 兼容验收

2026-11-06，锁定 ROCm 10.1.0 / HIP 7.16、R9700 gfx1201。**E5M2 功能验收完成，E4M3 兼容回归通过，性能仍待优化。**
原公开接口仍为229/229；本项扩展已有FP8接口的数据格式，不增加原接口分母或独立API数量。

## 实现及调用

BF16输入 → 每行/每列或128行/列块的动态量化 → E5M2字节 → 原生BF8 WMMA、FP32累加 → scale反量化 → BF16输出。
E5M2最大有限值57344，E4M3仍为448；RNE ties-to-even和satfinite。两种格式各自编译为不同扩展，避免误用编码。

```python
from leetcuda_rocm import fp8_gemm, quantize_fp8_weight, fp8_gemm_prepacked
out = fp8_gemm(a, b, fp8_format="e5m2", mode="row_col", use_ws=True)
weight = quantize_fp8_weight(b, fp8_format="e5m2", per_col=True)
out = fp8_gemm_prepacked(a, weight, per_row=True, use_ws=True)
```

默认参数继续选择E4M3。`FP8Weight.fp8_format`保留编码标记，预打包调用按权重格式选择内核；旧三参数构造默认E4M3。
四种scale组合、普通/独立producer-consumer调度、纯计算/在线/离线B均覆盖。
C++通过`LEETCUDA_ROCM=1`和`LEETCUDA_FP8_E5M2=1`选择E5M2，原C++接口及tile/stage仍有效。

契约：正尺寸、连续同设备BF16，K%16=0、N%8=0，16字节对齐，forward-only；输出/workspace不得别名输入。
输入有限，FP32 scale和倒数在正常有限范围；没有承诺FP32下溢/溢出域的全精度结果。
E5M2更大的表示范围不等于更小的量化误差。精度验收以独立量化参考为准，另记录对未量化BF16乘积的误差。

## 验收结果

| 范围 | 结果 |
| --- | --- |
| E5M2 Python，两张AMD卡 | 各756/756；主卡48个性能配置 |
| E4M3 Python兼容回归，两张AMD卡 | 各756/756；主卡48个性能配置 |
| C++两种格式 | 每种143/143及48个性能配置；含三个非默认tile/stage组合 |
| 默认API与格式标记 | 26/26，默认E4M3与显式E4M3逐位一致、在线/离线一致、非法格式拒绝 |
| 共享CPU输入 | 两端各800/800：320项量化字节/scale +480项GEMM输出 |
| 480份跨平台输出 | 全部在同一BF16门限内一致 |
| 同形状跨平台计时 | 两端各48个配置，逐端比较本机Torch BF16基线 |
| ISA | E5M2为`v_wmma_f32_16x16x16_bf8_bf8`，E4M3为`...fp8_fp8`；实际扩展/C++二进制均检查 |

Python专项覆盖三种seed、七种形状、五类特殊输入、全中点/符号零RNE、非默认stream、设备guard、边界与拒绝契约。
共享fixture有两种seed、非方阵及K1024，另有零组、动态范围、舍入和互逆尺度；独立CPU位编码与FP64乘积生成参考。
字节精确比较，scale使用原2e-7相对门限；BF16输出沿用atol=2^-10、rtol=2^-7，没有放宽。

AMD主卡物理GPU4/PCI83/HIP6、副卡物理GPU5/PCIa3/HIP7，物理GPU3未计算；身份在每份报告中。
CUDA E4M3使用固定上游原头文件，E5M2使用**显式格式扩展参考**：只替换格式类型、最大值、转换及MMA atom，保留TMA、WS和scale算法。
这不是原仓库已有E5M2实现的声明。原版头文件、生成后E5M2头文件及SHA256保存，参考生成方法在`fp8_cross_check.py`中。

## 性能

Python使用graph及5组交替40ms采样；C++每graph32调用、5组交替采样。所有计时路径先填NaN，再回放检查实际结果。
离线B准备成本单列；纯计算不含量化，在线包含A/B量化，离线B调用包含A量化。不同GPU耗时直接列出，不当作移植加速倍数。
当前实现仍慢于本机BF16库，后续继续优化量化和数据搬运。以下为Python两种规模、四种scale、两种调度的范围，数值为Torch/本实现：

| 格式 | 纯GEMM | 在线A/B量化 | 离线B调用 |
| --- | ---: | ---: | ---: |
| E4M3 | 0.515–0.698× | 0.109–0.431× | 0.235–0.656× |
| E5M2 | 0.515–0.698× | 0.108–0.428× | 0.236–0.657× |

完整逐配置耗时、所有原始样本、对未量化结果的误差、离线准备成本均在JSON中。
首次跨平台计时报告误标“每graph8次”，实际使用Triton自适应graph。修正描述并重跑两端所有配置，首轮原报告保存在`fp8_e5m2_20261106/cache_metadata_revision/`。
首轮ISA输出相对路径导致报告导出失败，原日志保留；修正为绝对路径并冻结native二进制后重新完整运行。
