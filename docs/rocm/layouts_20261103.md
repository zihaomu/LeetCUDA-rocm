# AMD 布局转置迁移：2026-11-03

11 个原 `mat_transpose_cute_*` 入口已迁移，原转置模块达到 **25/25**。
全套原始接口资格为 **150/229（65.50%）**，不是全仓 GPU 实现完成率。
实现位于 `kernels/rocm/mat_transpose_layouts.cu`，由 `load("mat_transpose")` 加载。

## 实现与契约

| 变体 | AMD 实现 |
| --- | --- |
| col2row_reg、row2col_reg | 16×16 tile，列／行线程映射，寄存器直接拷贝 |
| col_smem、row_smem | 16×16 LDS tile，分别转换行／列访问 |
| 上述两个 swizzled | 显式 `Swizzle<4,0,4>` 地址映射 |
| row_cvectorized，及 swizzled | 64×16 tile，每线程沿行取 4 个值，float4 输出 |
| row_rvectorized，及 swizzled | 16×64 tile，float4 输入，重排后输出 |
| row_rvectorized_swizzled_optimized | 8×128 tile，输入／输出 float4，转置 LDS 与 `Swizzle<2,3,2>` |

以 HIP 显式布局替换 CuTe，保留各入口的访存机制区别。优化版本加入 block barrier，
确保跨 wave 的 LDS 写入在读出前完成。CUDA CuTe 源码保留；本机没有 CUDA 回归结果。

新实现接收 FP32 连续二维 `x[M,N]` 和 `y[N,M]`，支持尾部和零元素。
向量化路径要求基地址 16 字节对齐；行尾或 stride 造成的局部非对齐访问使用标量拷贝。
拒绝别名、混合设备、梯度输入与越界的 32 位索引，device guard 恢复调用方设备，
使用 PyTorch 当前 stream。旧 14 个实现仍保留原有 tile/pack 限制。

## 正确性与性能证据

- [全套 GPU0 回归](qualification_20261103_layouts.json)：22 模块、150 原始接口、661 项通过。
- [GPU1 转置检查](layouts_device1_20261103.json)：25 接口、324 项通过，包括设备 guard。
  本次物理 GPU2 有其他任务占用，使用空闲物理 GPU1；未使用物理 GPU3。
- [详细布局报告](layouts_20261103.json)：252 项扩展检查、33 组性能对比。
  扩展检查覆盖默认／非默认 stream、非整块形状、NaN payload、正负零、无穷、空输入和非法输入。

性能采用 HIP graph、预分配并复用缓冲区、5 轮交替测量，每轮 40ms，以下为中位数。
参考是 PyTorch `out.copy_(x.T)`，不是对 AMD 最优转置库的比较；所有性能输入先检查数值。

| FP32 输入形状 | 本批最快变体 | 本实现 µs | PyTorch µs | 基线／本实现 |
| --- | --- | ---: | ---: | ---: |
| 256×512 | row_cvectorized_swizzled | 2.72 | 4.46 | 1.64× |
| 1024×1024 | row_rvectorized_swizzled_optimized | 6.79 | 32.70 | 4.82× |
| 4096×4096 | row_rvectorized_swizzled_optimized | 586.19 | 10016.28 | 17.09× |

其余教学变体没有统一性能保证。例如 256×512 的 col2row_reg 为 12.63µs，
慢于同轮 4.43µs 的 PyTorch 拷贝。报告保留全部原始样本，不只记录最快结果。
大矩阵基线的非合并访存会明显放大比值；这些结果不代表端到端模型收益。
