# NVFP4 完整链与5090共同输入验收

2026-11-06。**两张AMD卡与RTX5090各1560项通过，1560项跨平台比较全部逐位一致。**
本轮关闭既有NVFP4实现的完整链跨平台证据缺口，不新增原229接口分母，也不新增独立API。

## 范围与方法

13组冻结CPU输入：两个随机种子×3种shape，加零值、零分组、行/列动态范围、舍入ties、互逆尺度、scale下溢和饱和。
shape含M1/N8/K64、M129/N136/K320和M256/N256/K1024，覆盖尾行、短流水线、奇数tile数和长K。
四种level-1 scale组合、default/wide两种tile、WS/non-WS，分别验收纯量化输入GEMM、在线完整链、离线B。

| 每端检查 | 数量 | 门限 |
| --- | ---: | --- |
| A4/B4T打包字节、canonical SFA/SFB（含补齐行）、sa/sb | 312 | 码点/分组scale逐位相同；level-1 scale rtol=2e-7 |
| 纯计算/完整链/离线B输出 | 624 | atol=2^-10、rtol=2^-7，与既有FP4门限相同 |
| Graph replay | 624 | capture之后NaN重置；输出和边界canary复验 |
| 合计 | **1560** | 无失败、未放宽门限 |

CPU参考独立计算E2M1 RNE、E4M3 scale编码和五轴canonical重排，再对解码后的真实量化值做FP64 GEMM及BF16输出舍入。
全部输入、量化中间量和参考输出共390份tensor已从最终生成器重新生成并逐位验证；另2项生成器/参考源码hash检查通过。
非默认stream执行；输出前后各16个BF16 canary。本次没有引入新FP4生产算子修改，既有Python/C++同源实现保留。

## 硬件与原版关系

AMD使用ROCm10.1锁定镜像、gfx1201，主卡物理GPU4/PCI83，第二卡物理GPU0/PCI03。
5090使用专用目录、锁定CUDA镜像、上游`3dbd618`头文件和固定CUTLASS提交。
**本轮测试绑定直接编译未修改的原FP4头文件成功，没有启用constexpr兼容修复。**
此前整体bench编译中的constexpr问题保留历史语境，不能推断本轮原头文件也失败。

AMD使用E2M1/E4M3格式、精确FP16展开及FP16 WMMA/FP32累加，ISA审计23个特化均无scratch/spill。
CUDA二进制实际包含`OMMA.SF.16864.F32.E2M1.E2M1.UE4M3.4X`原生blockscale矩阵指令。
两端算术实现机制不同，当前1560项输出仍全部逐位一致。两端实际执行二进制已按SHA冻结，报告记录ISA/SASS hash。

## 性能

同一冻结M256/N256/K1024输入，每端48配置；各自与本机BF16 `torch.mm`比较。
使用自适应CUDA/HIP Graph重复、每次约40ms、五次交替采样，原始样本完整保存；每个配置先通过数值和Graph replay校验。
B离线准备独立计时，不隐藏在离线推理耗时中。

| 平台 | 路径 | 本机BF16库耗时 / 当前路径耗时 |
| --- | --- | --- |
| hip | quantized | 0.075～0.098× |
| hip | full | 0.067～0.087× |
| hip | offline_b | 0.070～0.091× |
| cuda | quantized | 0.581～1.254× |
| cuda | full | 0.316～0.759× |
| cuda | offline_b | 0.476～1.028× |

**AMD性能尚未达标。** 当前小矩阵FP16展开及数据搬运成本很高；这些数据仅代表本shape、当前实现和各自本机库基线，不能解释为跨GPU等算力对比。
零spill并不意味着内核已高效。后续继续分析展开、LDS布局、tile与WS调度，保持该原始基线及数值门限。
