## 2. 下一批的固定执行顺序

下列三个接口均使用公共前缀 `flash_attn_mma_stages_split_q_tiling_qkv_acc_f32_`。

| 顺序 | 接口后缀／任务 | 实现内容 | 进入下一步的条件 |
| --- | --- | --- | --- |
| P0 | 冻结基线与补验 | 保存当前源码、fixture、设备身份；补双设备契约检查；在同一卡重测非 swizzle 父实现 | 基线无数值回归，测量方法固定；设备补验不能执行时单独标为待补 |
| P1 | `swizzle_q` | 仅改变 Q 的 LDS 地址映射，配套修改写入和 WMMA 读取 | 该入口通过功能门槛 F1～F5，完成性能测量；明确性能是否达标 |
| P2 | `swizzle_qk` | 在已验证 Q 布局上增加 K 的 LDS 映射 | 同上，并分别检查 Q/K 两个映射及 stage 槽不重叠 |
| P3 | `swizzle_qkv` | 再增加 V 的映射，处理 V 转置读取与 PV fragment | 同上，并验证 V 装载、转置和读取使用同一映射 |
| P4 | 批次收尾 | 全库回归、全部已支持接口的共同输入对照、清单及报告更新 | F0～F6 全部通过；性能按独立门槛 P 判定 |

P1～P3 按单个入口执行 F1～F5；下文的 372/42/54 等数量是三个入口累计目标。

完整接口名：

1. `flash_attn_mma_stages_split_q_tiling_qkv_acc_f32_swizzle_q`
2. `flash_attn_mma_stages_split_q_tiling_qkv_acc_f32_swizzle_qk`
3. `flash_attn_mma_stages_split_q_tiling_qkv_acc_f32_swizzle_qkv`

选择依据：已有非 swizzle tiling-QKV 实现、14 个 D×stage 配置和精度检查可复用；
逐步增加映射能定位 Q、K、V 各自引入的问题。历史 5090 探索中三个入口各有 3 个
通过用例，但这些小样本不足以替代本计划的扩展验收。

这里的 swizzle 是 **LDS 中的地址排列**。保留三个入口的实际差异，可以共享模板，
但不能把三个名字全部指向不改变布局的父实现。AMD 映射允许针对其 wave/WMMA

## 3. 下一批必须保留的接口与精度约定

| 项目 | 目标 |
| --- | --- |
| 输入／输出 | 连续 FP16，同设备、同 `[B,H,N,D]` 形状；输出不能与输入共享存储 |
| Head dimension | **32、64、96、128、256、512、1024** |
| Stage | 实现 stage 1/2 的不同流水线；保持 `stages<=1 → 1`、`stages>1 → 2` |
| 矩阵计算 | QK、PV 使用实际 AMD WMMA，FP32 累加；P 转为 FP16 后参与 PV |
| Softmax 状态 | max/sum 使用 FP32 |
| 输出累加状态 | D<256 为 FP32；**D>=256 每个 key block 后舍入为 FP16** |
| Query/key tile | D<128 为 64×64，否则 128×128；保持大 D 的状态舍入频率 |
| AMD 扩展边界 | 延续父实现的 N 尾部、空 B/H/N 与未对齐连续视图支持，单独对参考验证 |
| 本批范围 | 前向；不新增 BF16、causal、GQA、dropout、任意 mask、backward |

上述约定已核对原三个 swizzle 源文件的 dispatch 和 `kOStorageAccFloat32` 设置。
原 CUDA 要求 N 对齐到 query/key tile；CUDA 共同输入只取其合法范围，
AMD 新增尾部能力不强行在原 CUDA 上执行。非法输入应明确拒绝，不能静默读写越界。

实现阶段优先保留当前 D>128 的 128 列输出分片，以隔离布局变化。
消除大 D 重复 QK 作为后续独立优化，不和首次 swizzle 验收混成一个无法归因的改动。

### F1：独立参考与 5090 原版对照

- 复用上一批 **62 组冻结 CPU fixture**，每个新入口运行两种 stage：
  **每端至少 62×2×3=372 项**，AMD 与原 CUDA 均通过独立 FP64 参考。
- 沿用 `atol=0.003, rtol=0.003`，实际按现有程序与 `reference.half()` 比较，
  同时保存相对 FP64 原值的最大误差；要求有限输出，不能放宽容差或筛去失败样本。
- 372 组 CUDA/AMD 输出须全部在同一容差内一致；逐位一致数量单独报告，不要求全部逐位一致。
- 覆盖两个随机种子、全部 D、N=128/256/384、batch/head 组合、零 V、均匀 softmax、
  大 logits、正负抵消，以及 D=256/512/1024、N=4096 的长序列。
- 两端输入文件、逐 tensor、源码、头文件、测试脚本、二进制和输出均记录 SHA256。
  原 CUDA 若有故障，保留原版结果；修复版另建报告，不覆盖原版证据。

### F2：存储精度及布局一致性

- 3 个入口 × 7 个 D × 2 个 stage，完成 **42 项**输出状态检查。
- 使用上一批 Q=K=0、32 个 key block、首块 V=1、其余 V=2^-11 的构造输入，
  对独立 CPU 递推逐元素精确比较。D>=256 应为 **0.03125**，不得变成全 FP32 状态的 **0.03173828125**。
- 对每种实际使用的 LDS tile 枚举映射：地址有界、无碰撞、写入与读取互逆、不同 stage 槽不重叠。
  加入带行列标识的 tile 搬运检查，特别覆盖 V 转置读取及 D=96、128、256、1024。
- 与同机非 swizzle 父实现对照。只改变地址、不改变算术顺序的配置要求逐位一致；
  如确需改变归约／指令次序，先明确差异，继续执行相同数值与状态精度门槛。

### F3：边界、输入契约与运行时行为

- D 全集、stage 1/2、至少两个随机种子，覆盖 N=1/17/63/65/127/129/257。

## 5. 性能门槛 P

### 5.1 固定比较对象与形状

每个新入口比较同一卡、同一次实验中的三个对象：新实现、已有非 swizzle tiling-QKV、Torch SDPA。
另记录 5090 原 CUDA 耗时，但不把不同硬件的耗时比当成 AMD 移植优化倍数。

固定 B=1、H=4，以下 9 组 `(N,D)` 均运行 stage 1/2：

| N | D | 观察目的 |
| ---: | ---: | --- |
| 128 | 32 | 小规模开销 |
| 256 | 64 | 常见较短序列 |
| 512 | 64 | 中等序列 |
| 1024 | 64 | 较长序列 |
| 1024 | 128 | 更大 QK/PV tile |
| 256 | 256 | FP16 输出状态切换后的形状 |
| 512 | 256 | 大 D 带宽与同步成本 |
| 512 | 512 | 输出分片及重复 QK 成本 |
| 512 | 1024 | 最大 D 与 SDPA 派发差异 |

因此每端新增实现至少有 **3×9×2=54 个性能配置**；父实现与 SDPA 必须当场重测。
每个形状单独记录 SDPA 是 flash、math 或其他后端，不能用 D=1024 的 math 基线结果
宣称超过 fused FlashAttention，也不能拿上一批不同卡上的绝对耗时作为本批硬门槛。

### 5.2 测量与判定

- 固定每 graph 8 次调用，预热后交替测量；每配置 **5 组样本、每组至少 40 ms**，保存原始数据。
- 完成 **3 轮独立测量**，顺序轮换；只在正确性和 replay 检查通过后计时。
- 使用中位数；记录温度、频率及占用。候选或父实现在同一配置的三轮中位数
  `(最大值-最小值)/三轮中位数 > 5%` 时，标为测量不稳定，排除干扰后复测，不挑最好一轮。
- **每个入口的性能达标 P**：三轮均满足，18 个固定配置的
  `几何平均(T_parent/T_new) ≥ 1.05`，且任意配置 `T_new/T_parent ≤ 1.10`。
- **整批性能达标**：三个入口分别达到 P，且资源优化目标无遗漏。
  冲刺目标为最终 QKV swizzle 在 D=64/128 的四个形状、两种 stage 上几何平均加速达到 **1.10×**。
  冲刺目标不替代每配置退化检查。
- 已支持入口的受影响公共路径，所有合法性能配置须当场重测；相对冻结基线退化超过 10%
  时保留旧实现路径，继续优化候选，不覆盖原性能路径后宣称无回归。

这些数值是**本计划预先设定的工程验收目标**；执行后逐项判定，未因结果调整门槛。
若功能通过而 P 未通过，发布状态写成“功能支持／性能待优化”，保留详细耗时与原因。

- 原 `split_kv` 源码是在**同一 CTA 内跨 warp 划分 KV**，包含 block 级 softmax max/sum

- 16 个 `numerical_rejected`（HGEMM 11、HGEMV 2、BF16 Reduce 3）作为独立精度工作包。
  保持原失败证据；FP16/BF16 语义匹配、FP64 门限通过和显式 FP32 精度提升分开记录。
  若采用升级精度方案，须明确更新契约与库存标记、重新通过数值及跨平台门槛，不能静默改名或放宽门限。

FP8/FP4 性能、FFPA、独立 C++ 构建与其他非绑定源码继续按
[整体迁移计划](leetcuda_rocm10_migration_plan.md)跟踪，不混入 229 个接口的支持率。
