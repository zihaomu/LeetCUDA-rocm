# FFPA 三种 Split-D 前向实现验收

2026-11-06，ROCm10.1/HIP7.16、gfx1201。**三个独立 FFPA 路径完成功能验收**；性能差距仍保留。
新增 `leetcuda_rocm.ffpa_attention` 一个独立计算 API，含三个真实实现分支。
原 Python 接口分母仍为229/229，独立 AMD 计算 API 从7增至8；不能把三种变体另加到229的分母。

## 使用与迁移差异

```python
from leetcuda_rocm import ffpa_attention
out, lse = ffpa_attention(q, k, v, variant="non_ws",
                          stages_qk=2, stages_v=3, return_lse=True)
```

输入为同设备连续 FP16，Q `[B,H,NQ,D]`，K/V `[B,H,NK,D]`。
D 支持64/128/192/256/320/384/448/512/1024；Sk/Sv分别为1～3。
支持NQ≠NK、空B/H/NQ/NK、序列尾部、未对齐连续视图、调用者提供O/LSE、当前stream和device guard。
仅前向；不支持BF16、GQA、causal、mask、dropout或autograd。这些训练能力属于独立的 `attention` 接口。
输入必须有限；无运行时全量值扫描。

| variant | 原 CUDA | AMD 实现及保留机制 |
| --- | --- | --- |
| `async` | `ffpa_split_d_cute`，cp.async，QK64/PV64 | 显式128-bit VMEM→VGPR预取→LDS，两条独立环；同一CTA完成全部D，无输出分片重复QK |
| `ws` | `ffpa_attn_tma_mma_ws_split_d_cute`，TMA、128 producer+128 consumer线程 | 32线程producer和256线程consumer独立前进；QK/V分别ready/done序号和acquire/release，真实多槽复用 |
| `non_ws` | `ffpa_attn_tma_split_d_cute`，QK32/PV64、FA4条件rescale、LSE、LDS/TMA写出 | QK32/PV64，保持8个log2单位的条件rescale与自然对数LSE；复用LDS作输出暂存并向量写出 |

三者均实际执行FP16 WMMA，QK/PV及在线max/sum/输出状态为FP32，P转FP16后用于PV。
AMD根据64KiB LDS限制使用BR16/BC64；原前两者BR64/BC64，原第三者BR128/BC128。
分块及舍入顺序有差异，不宣称逐位一致；不宣称AMD有TMA指令。
每个环静态预留三槽，Sk/Sv控制实际槽数和预取距离；stage1不代表更小的静态LDS。
D1024、任意序列尾部，以及前两者的LSE是明确的扩展验证范围。

输出门限固定atol=rtol=0.003，LSE固定atol=rtol=2e-5，直接对CPU FP64值比较。

## 已解决问题与资源

1. 原CUDA async的stage3尾部不再发起新预取，却未等待剩余组排空，D64出现18项错误。
   这是根据代码及实验定位的同步缺陷。`cp.async.wait_group N`允许最近N组仍待完成，N=0才等待全部，见[NVIDIA PTX说明](https://docs.nvidia.com/cuda/archive/12.0.0/pdf/ptx_isa_8.0.pdf)。
   修复只在QK/V的生产尾部增加wait_group0及CTA同步；原版、修复版分别运行，均保留源码/二进制hash，未修改容差。
   fork的CUDA头文件也包含该修复，原始`original/`快照保持原状。
2. 初版HIP有6个特化发生12～76字节scratch。QK外层禁用展开后降至4个；V循环保留并按固定累加器索引分派后全部清零。
   中间候选和失败的CUDA测试绑定编译日志均保留。
3. 最终27个特化均有WMMA与128-bit global load，VGPR124～214、spill=0、scratch=0。
   async/WS的LDS为61888B，non-WS为46528B；合法但前两者高于48KiB资源优化目标，不能称已充分优化占用率。

N4096/B1/H2/D128的三条路径额外显存均为**2129920B（2.03125MiB）**，精确等于O+LSE。
对应密集FP16概率矩阵为64MiB；验证同时检查均匀Attention的O=1及LSE=ln4096。

## 性能

两端均用相同冻结输入B1/H2/N384、9种D×3路径×5种stage，共135配置。
每graph8次调用，五组交替样本、每组目标40ms；比较各自GPU上的Torch SDPA，不用跨GPU耗时比声称优化收益。
AMD基线在D≤512为fused FlashAttention，D1024为math。

| AMD路径 | Torch SDPA / 本实现 |
| --- | ---: |
| async | 0.304～0.831× |
| ws | 0.062～0.190× |
| non_ws | 0.391～1.171× |

仅D1024 non-WS约1.10～1.17×，比较对象是math SDPA。其余被测配置仍慢，尤其WS；后续继续改善producer搬运吞吐、LDS占用和query并行粒度。
C++的27组计时是100次调用的事件平均、没有基线，不与上述graph结果混用。
