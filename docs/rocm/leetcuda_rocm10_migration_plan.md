## 工作量估计

以单人等效工程投入、当前 R9700 主机可用为前提，**功能迁移和完整回归约 4～8 人周**；
若要求主要 workload 的性能接近成熟 ROCm 库，再预留 **2～4 人周**。
这是根据当前源码范围与已遇到的问题给出的规划区间，不是代理运行时长或交付日期承诺。
低精度 GEMM 性能、训练路径和架构相关同步实现的估计不确定性较大；每完成一个里程碑重新评估。

## 验收原则

1. 固定 ROCm 10.1.0 镜像、Torch/Triton 配对和 gfx1201；实验使用项目启动器和独立缓存。
2. 覆盖原有计算接口及单独列出的 C++/Triton/FP8/FP4/FFPA 路径，保留算法标识、布局与
   累加精度说明。API 兼容、功能等价、原调度机制复现分别标记，不混为一个完成数字。
3. NVIDIA 专有指令或依赖允许换成明确标识的 AMD 实现。不得将所有变体静默别名到
   同一基线函数，也不得忽略 stage/split/layout 等参数或把不支持的指令变为空操作。
4. 每批使用独立数值参考、真实 GPU、非默认 stream 和边界形状；适用时补测第二张卡、
   设备 guard、输入契约、矩阵指令与性能。性能测量与 correctness 分开，记录原始样本。
5. 低精度算法可以增加独立算术语义验证，但不得改写已经失败的 FP64 精度结论或静默放宽
   原门限。每个接口分别报告“语义正确”“精度门限”“性能”，未满足的要求保持可见。
6. Nsight、TensorRT 等 NVIDIA 工具本身不移植；相关演示若属于交付范围，提供 AMD
   对应流程并明确替换关系。CUDA 历史路径不在 AMD 主机上虚构回归结果。
7. 完成意味着接口清单、补充实现清单、构建入口和验证报告闭合；没有证据的项目不能标完成。
   如存在目标硬件无法原样复现的机制，提供经过验证的替代方案及限制，不以名称兼容冒充复现。
