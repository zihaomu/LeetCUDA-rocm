# B7：独立生产者/消费者 WS-HGEMM 验收

日期：2026-11-06。新增 `ws_hgemm_naive_cute` 后，原接口 **213/229（93.01%）**。
B1–B7的43个原待迁移接口完成了功能验收；16个精度未验收入口、性能和整体补充范围继续推进。

## 实现与契约

原CUDA采用一个32线程生产者、四个消费者warp、三槽pipeline；128×256×32 tile
需要73728 bytes的tile存储，超过本机AMD每CTA64KiB限制。
AMD采用 **64×128×32、一个生产者wave和四个消费者wave、三槽LDS环**。
总LDS36924 bytes；消费者使用原生FP16 WMMA，**明确将累加从FP16升级为FP32**。

- A逻辑[M,K]、B逻辑[K,N]、C[M,N]，均为连续FP16；**B原始存储仍是[N,K]行主序**。
- 每槽ready序号由生产者发布；四个独立done序号由消费者发布。覆盖槽前等待四者完成旧序号。
- acquire/release原子访问配合wave fence；只有初始化使用CTA barrier，K循环没有CTA barrier。
- 生产者一次发出24个128-bit global load，然后等待并发布当前LDS槽。消费者独立处理先前槽。
- 未对齐地址和M/N/K尾部使用有界装载；空M/N返回，K=0输出零；保留当前stream和device guard。
- dtype/rank/shape/stride、别名、requires_grad、混设备、32-bit索引及网格范围均检查。
- 私有同步control保留同样tile和WMMA顺序，但逐tile使用CTA同步；公开入口不是普通GEMM别名。

## 正确性、调度和集成

| 检查 | 结果 |
| --- | --- |
| 两张AMD专项 | 各 **131/131**：15共享输入、65边界/输入不变/设备/stream、15同步逐位对照、36进度审计 |

| 独立进度 | 受控延迟消费者后，各CTA生产者可领先3个tile；生产量及四组消费量完全一致，零超时 |

| 专项跨平台 | 两端参考通过的 **13/13** 比较通过；2个原CUDA失败单列，不能计为跨平台通过 |
| 全库AMD | **25模块、213接口、1175/1175** |
| 全接口共同输入 | **430/430**两端独立参考及跨平台比较通过 |
| 资源 | 16条静态WMMA，VGPR166，零spill/scratch，LDS36924；仅1条barrier signal与1条barrier wait |

专项覆盖两个种子、长K4096/8193、奇数tile/形状、零维、抵消、互逆尺度、未对齐A及packed B、
输入保持不变、输出canary、8条并发stream各4次排队、跨设备拒绝与device guard恢复。
15个共享输入来自CPU冻结文件；原CUDA仅改current stream发射，原算法保持不变。
全接口回归使用5090的ported工作树，专项使用original快照，两者证据分开。

主卡为物理GPU4/PCI83/HIP6；第二卡为物理GPU5/PCIa3/HIP7。
开始时主卡可见第二设备为物理GPU6/PCIc3，做小型设备契约检查；该卡随后有其他任务，
第二卡完整专项改到空闲的物理GPU5。锁定ROCm10.1/HIP7.16/Torch2.14，禁止物理GPU3参与计算。

## 失败研究与性能

首轮数值正确但进度验收失败：消费者仅延迟64次sleep时，生产者最多领先1个tile。
扩大私有审计的消费者延迟到4096次sleep后，三槽领先量达到3，36项全部通过。
这项实验用于证明角色可以独立推进，**不把人为延迟结果当作真实workload性能提升**。
正常输入下，批量装载后的完整tile已观察到领先2；小尾部仍可能只有1。

随后消除生产者每个vector的串行global读取，改为先发出24次向量读取，再发布LDS。
初版256/1024/2048规模耗时约0.03779/0.27191/1.87951ms，最终约0.01047/0.08357/0.52860ms；
这些不同轮次的记录用于说明瓶颈，不替代同次实验的同步control比较。

每graph8调用、20ms×5组交替计时；先验证独立参考，再把输出填NaN并replay验证执行。

| 方阵规模 | AMD耗时ms | Torch/AMD | 同步control/独立流水线 |
| ---: | ---: | ---: | ---: |
| 256 | 0.010475 | 0.4649× | 1.1423× |
| 1024 | 0.083569 | 0.2946× | 1.0607× |
| 2048 | 0.528598 | 0.2864× | 1.1218× |

独立流水线快于同算术的同步control；当前仍比Torch慢约2.2–3.5倍，性能待优化。
原CUDA的1024/2048性能输入未通过FP64精度门限，虽graph replay有效，其耗时仅保留为失败算法的测量，不能作合格性能宣传。
