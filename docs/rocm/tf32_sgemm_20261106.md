# B6：三个 TF32 SGEMM 入口验收

日期：2026-11-06。新增3个入口后，原接口 **212/229（92.58%）**，SGEMM **17/17**。
B6功能验收完成，性能仍待优化；继续B7、16个精度工作包与整体补充范围。

## 算术契约与实现

目标 gfx1201 没有原 CUDA WMMA TF32 对应的原生矩阵格式。两个 WMMA 入口采用
**RNA-TF32 高位／残差分解、BF16 WMMA 和 FP32 累加**；cuBLAS入口采用
**显式分解后的三个 hipBLAS 乘积**。不存在普通FP32函数别名，也不宣称原生TF32指令。

设 `h(x)=RNA_TF32(x)`，`l(x)=RNA_TF32(x-h(x))`，公开实现计算
`h(A)h(B) + l(A)h(B) + h(A)l(B)`，省略二阶残差积。这是明确的
**TF32x3 输入精度升级**，不等于原单个TF32乘积。每个TF32分量拆成两项BF16，
矩阵路径每个BK8局部积使用12次BF16 WMMA；再把局部积累加到运行FP32状态。
私有单TF32 control 与独立舍入参考比较，防止把升级后的成功误称为复现原语义。

- 两个矩阵入口保留128×128/BK8、8个wave、静态或动态LDS环、真实stage深度和block swizzle。
- 静态stage2/3/4；动态2/3/4/5；其他stage回到2。swizzle stride必须为正的256倍数。
- `global_load_b128` 寄存器预取、当前WMMA、显式wait、LDS发布的编译后指令顺序已验证。
- 非零输入绝对值在 `[2^-96, 2^112]` 内使用BF16精确分解；范围外的tile使用明确标识的
  FP32 scalar FMA备用路径。BLAS splitter对该范围外数值保留完整high值、low=0。
- FP32连续同设备 A[M,K]/B[K,N]/C[M,N]；尾部、空M/N/K、非对齐连续视图支持。
- AMD保持输入不变；**原CUDA WMMA会原地把A/B舍入到TF32**，此行为差异明确记录。
- 输入dtype/rank/shape/stride、别名、requires_grad、混设备、索引/网格超限均有检查；前向接口。

所有计时先验证独立参考，并在graph capture后将输出填NaN再replay确认实际执行。

环境：锁定ROCm10.1/HIP7.16、Torch2.14+rocm10.1、gfx1201；主卡物理GPU4/PCI83/HIP6，
复验物理GPU6/PCIc3/HIP5。完整镜像身份和hash在JSON；物理GPU3没有参与计算。

## 资源、失败候选与性能

7个BF16 WMMA特化均 **零spill、零scratch**。静态VGPR245–246、动态239–241；
静态LDS最大32896 bytes，动态stage5为40960+160 bytes；都在64KiB以内。
每个特化确认96条静态BF16 WMMA以及真实load→WMMA→wait站点。

初版极端指数分支采用FP64局部乘积，整个kernel达到VGPR256、spill81–139、
scratch328–552 bytes，消除了有效预取次序。诊断和失败研究都保留：

- 单纯缩短片段生命周期：210项逐位一致，但性能仅原版0.744–0.776倍，未采用。
- 临时去掉极端分支：定位了资源瓶颈；该诊断版本不对用户发布。
- 64×64 tile：无稳定加速，动态版仍少量spill，未采用。
- **保留128×128，极端分支改为FP32 FMA**：210项逐位一致，零spill，同卡六个性能配置改善1.067–1.184倍。
- 另一早期原型把每项残差直接累加运行总和，K8193误差0.0006706超门限；改为BK8局部归约后降到0.00001503。失败JSON保留。

最终性能为同卡 `Torch.mm时间/本实现时间`；每graph8调用、20ms×5组，全部原始样本保留。

| 接口 | 配置数 | 几何平均 | 最小–最大 |
| --- | ---: | ---: | ---: |
| `sgemm_wmma_m16n16k8_mma4x2_warp2x4_stages` | 18 | 0.2188× | 0.1804–0.2579× |
| `sgemm_wmma_m16n16k8_mma4x2_warp2x4_stages_dsmem` | 24 | 0.2225× | 0.1806–0.2737× |
| `sgemm_cublas_tf32` | 3 | 0.2739× | 0.1868–0.3361× |

当前矩阵路径约为Torch的4.5倍耗时，BLAS三乘积也有额外量化、临时空间和多次调用成本。
本批仅关闭功能与性能测量，不宣称与成熟库性能接近。
原CUDA cuBLAS每次创建/销毁句柄，实测graph capture失败；原失败日志保留，3个规模使用eager
事件计时，包含主机提交空隙和句柄开销，不能和AMD纯graph延迟当作同口径加速比。
原CUDA动态stage5、关闭swizzle时还存在switch fallthrough，会额外执行stage2；原版计时保留该行为，AMD只执行选中的stage5。

旧SGEMM/HGEMM原GPU指令段与冻结证据比较，见下方旧指令审计；所有原209接口仍通过全库与跨平台检查。
